# Проверка конструктора — 29 сентября 2026

## Исправлено

- Сохранение истории вызывало отсутствующую функцию `normalizeEmail`. Из-за этого ручное сохранение и публикация могли обрываться до запроса к серверу.
- Ответ публикации записывался в текущий открытый раздел. Если во время ожидания продолжить редактирование или перейти к другому разделу, новые данные могли замениться отправленной ранее версией. Теперь результат привязан к исходному разделу и его версии.
- Сбой синхронизации больше не выдаётся за конфликт с более новой облачной версией.
- Повторная отправка публикации во время текущего запроса заблокирована; ожидание ответа ограничено 45 секундами.

## Автоматические проверки

Браузерные тесты используют отдельное тестовое хранилище и подменяют ответы сервера публикации. Они не входят в реальные аккаунты и не записывают данные в Firebase или GitHub.

Проверяются редактирование, предпросмотр, подразделы и вложенные блоки, смена типа блока, восстановление после перезагрузки и потери сети, разрешение настоящего конфликта версий, ограничения доступа, состав пакета публикации, повтор после ошибки сервера, правки и переключение разделов во время отправки.

## Проверка действующего сервера

Существующий Apps Script отвечает на запрос `capabilities`: HTTP 200, `success: true`, `notePublisher: true`, `noteDeletion: true`. Сборка страниц из исходных разделов и проверки правил публикации проходят локально.

Это подтверждает доступность серверного обработчика, но не действительность его секретного `GITHUB_TOKEN`. Авторизованную запись из аккаунта владельца в этой проверке не выполняли. Для окончательной проверки нужно опубликовать одну запланированную правку владельцем и дождаться успешного развёртывания GitHub Pages. Обновлять Apps Script или правила Firebase для внесённых исправлений не требуется.
