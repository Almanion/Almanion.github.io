# Проверка 0.12.0 — свободное строительство

Контроль завершён 29 октября 2026. Новая операция: frontier-8, формат
сохранения 10. Это отчёт о локальных проверках; результат GitHub Actions
и публикации нужно проверять отдельно по конкретному коммиту.

## Что входит в версию

Свободное размещение построек, реальный дрон-строитель, независимые очереди
производств, точки сбора и управление группой производств. Сохраняются
незавершённые работы, груз и пути работников. Старая операция продолжает
использовать прежние правила. Следующее расширение экономики ещё не включено.

## Исправленные ошибки

1. При начале размещения камера выходила из общего вида, но кнопка обзора
   до следующего кадра сохраняла старое aria-pressed. Повторное обновление
   интерфейса после фокусировки синхронизирует их сразу. Регрессия проверяет
   состояние непосредственно после начала размещения, без маскирующей задержки.
2. Навигационный слой построек применялся к начальной расстановке работников
   старой карты до преобразования её координат. Для старых профилей возвращён
   исходный порядок. Проверены исходные координаты двух работников и точное
   равенство всего начального состояния и первых 6000 шагов frontier-7
   с публичным b940774.
3. После истощения домашней жилы и потери всех работников нельзя было обучить
   нового строителя, даже имея сплав для дрона и нового узла. В frontier-8
   база может обучить платного дрона и при пустой жиле: обычные 50 сплава,
   18 секунд, прежние ограничения очереди и населения. Руда не добавляется.
   Старые профили сохраняют прежнее правило. Тест проходит восстановление
   сохранения в очереди, строительство узла за 160 и возобновление добычи.

Четыре сбоя короткого набора: устаревшая ожидаемая версия сохранения 9;
тест конфликта вкладок ждал оплату уже при выборе макета; последний снимок
нового теста открывал каталог без перехода в тактическую паузу; отдельный
сценарий Eclipse превысил 30 секунд при одновременных тяжёлых прогонах.
Первые три исправлены в тестовом стенде. Eclipse прошёл изолированный повтор
без изменения его кода. Первый набор целиком зелёным не объявляется;
GitHub Actions должен повторить весь применимый набор на публикуемом коммите.

Полные прохождения не получают дополнительных ресурсов, не телепортируют
героя и не удаляют противников. В браузерном длинном тесте ускоряется только
время: выполняются все фиксированные шаги симуляции, покупки и приказы идут
через настоящий интерфейс. Во время ускоренного прогона подавляется основная
растеризация холста; финальный экран рисуется и проверяется отдельно.
Поэтому этот тест подтверждает игровой цикл, но не измеряет FPS.

Обе браузерные победы проверены визуально: соответствующая ветке подпись,

арсенал, минимум два построенных узла, восстановление без изменения ресурсов,
пределы объектов, эффектов, следов и размера сохранения. Четыре основных размера:
1440×900, 390×844, 320×568 и 844×390. Проверены отмена, повторные нажатия,
поворот, пауза, поражение и запуск новой операции. Физические iOS/Android
устройства отдельно не проверялись.

## Темп и дополнительное восстановление

Первое браузерное проникновение заняло 47:54. Проверочный игрок прокладывал
пути по неподвижной карте, игнорируя новые корпуса в сырых снимках состояния.
Он также резервировал лишние 50 сплава для второго работника при уже имеющемся
строителе. Исправления маршрута и планирования покупок дали 32:42 при прежних
ценах, добыче и боевых параметрах. Разница игрового времени не объясняется
скоростью браузера или видеокарты.

На той же горной карте исходная frontier-7 из b940774 проходит осаду за
29:38,65. После исправления начальной расстановки текущая frontier-7 проходит
за 29:39 (округление), проникновение — 27:08. Старый ориентир 23:24 для
плоской frontier-6 нельзя считать прямым сравнением с горной картой.

Ориентир 20–25 активных минут автоматический игрок пока не выполняет.
Длительность партии человека не измерена. Это открытый вопрос темпа для
следующего этапа экономики: отдельно сравнивать разведку, ожидание добычи,
строительство и бой. Цены и скорость добычи ради прохождения теста не менялись.

Дополнительный эксперимент продолжил неудачную осаду с 25:41,2, пустой
домашней жилой, без работников и с 233 сплава. Платный дрон и новый узел
вернули добычу; к общему времени 50:00 живы пять работников, всего доставлено
4308 вместо 3008 сплава. Однако этот проверочный игрок остался на второй
ступени и не выиграл до прежнего предела 3000 секунд. Утверждение о полной
победе из этого неблагоприятного сохранения **не подтверждено**; эксперимент
завершился неуспешно. Он подтверждает возможность восстановления дохода,
а не гарантирует победу после любых потерь. Штатные обе ветки с начала
операции завершились в пределах того же ограничения.

## Почему изменены тесты

- Старый тест магазина явно запускает frontier-7: его цены, длительности,
  возврат 47 и ограничения очереди сохраняются. Отдельный новый тест проверяет
  frontier-8 на экране 320 пикселей, обычный кошелёк, роль арсенала, оплату
  казарм при подтверждении, единственную покупку при двойном нажатии и возврат 37.
- Длинный тест действительно размещает здания и подтверждает точный платёж.
  Пилот использует навигацию с корпусами и перестраивает путь при их отмене.
  Регрессия проверяет каждый сегмент по реальной геометрии, неизменность
  исходного снимка и перепланирование после удаления препятствия.
- Тест двух вкладок различает бесплатный макет и оплату: до подтверждения
  конфликт скрыт и расход нулевой, после него другая вкладка блокируется,
  Esc не снимает блокировку, последняя версия содержит расход 120.
- К пределу 3000 игровых секунд и браузерному тайм-ауту 40 минут послаблений
  нет. В CI добавлена frontier-8 к обеим веткам, перед ними выполняется полная
  симуляция строительства. Общий тайм-аут задания увеличен с 50 до 60 минут
  из-за этой дополнительной обязательной проверки.
- .local-qa исключена из Git и проверки размеров публичных файлов: это частные
  журналы и снимки, а не поставляемые ресурсы. Согласованный ранее бюджет JS — 5 000 000 байт;
  лимиты запросов и внешних подключений сохранены. CSS 35 000 байт относится
  к панели строительства. Ради исправления тестов эти пороги не менялись.

## Воспроизведение

Штатные команды из корня репозитория:

~~~sh
npm ci --ignore-scripts
npm run ci
npm run test:rules
node tests/signal-frontier-construction.test.js
node tests/signal-frontier-construction-operation.integration.js
npx playwright test --grep-invert "long (siege|infiltration): full operation"
npx playwright test e2e/signal-frontier-campaign.spec.js --grep "full operation frontier-8 through real controls" --workers 1 --retries 0
~~~

Для сравнения совместимости извлечь git archive b940774 в отдельный каталог
и передать его путь команде
~~~sh
node tests/helpers/signal-frontier-legacy-compare.cjs <каталог-с-исходниками-b940774>
~~~
Она сравнивает все поля начального состояния и состояние каждые 60 шагов
на протяжении 6000 шагов при одинаковых приказах исходного проверочного игрока.
